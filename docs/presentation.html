의자에 앉은 줄 (배열)

  • 가운데 사람이 나가면 뒷사람이 모두 한 칸씩 이동
  • 사람이 n명이면 최대 n번 이동 → O(n)

손잡은 줄 (연결 리스트)

  • 나간 사람의 양옆 두 명만 다시 손을 잡음
  • 줄이 아무리 길어도 2번 → O(1)

부록 A1 · 꼬리 질문 대비 ①

자료구조 선택에 대한 질문

센티널 노드는 메모리 낭비 아닌가?

리스트마다 빈 노드 2개(각 56바이트)입니다. 대신 삽입 · 삭제에서 ‘맨 앞인가, 맨 끝인가, 하나뿐인가’ 분기가 모두 사라져 버그 여지가 줄어듭니다.

버킷마다 리스트 객체면 무겁지 않나?

빈 칸은 None 이고 첫 키가 올 때만 리스트를 만듭니다(지연 생성). 마지막 키가 빠지면 다시 None 으로 돌립니다.

해시 충돌을 노린 공격은?

FNV-1a 는 암호용 해시가 아니라 일부러 같은 칸에 몰리는 키를 만들 수 있습니다. 실서비스라면 시드를 섞은 해시(SipHash 등)를 씁니다. 이번 범위는 CLI 단일 사용자입니다.

부록 A2 · 꼬리 질문 대비 ②

TTL 과 실제 Redis 에 대한 질문

같은 키에 EXPIRE 를 계속 걸면?

힙에 옛 항목이 쌓이지만 꺼낼 때 버려지고, 살아있는 TTL 키의 2배를 넘으면 힙을 다시 만듭니다(64개 이하일 땐 그냥 둠).

컴퓨터 시계를 바꾸면 TTL 은?

time.monotonic 기준이라 영향이 없습니다. 이 시계는 거꾸로 가지 않습니다. 테스트에서는 가짜 시계를 주입합니다.

실제 Redis 도 이렇게 하나?

원리는 같고 규모 대응이 다릅니다: 근사 LRU(샘플링), 점진적 리해싱, 만료 처리 시간 상한. 오늘 4-2 개선안이 바로 그 방법들입니다.
